# 강호비급 (江湖祕笈) — 설계서

작성일: 2026-08-01
상태: 승인됨 (구현 계획 작성 대기)

## 1. 개요

무명의 협객이 초식(카드)을 모아 강호를 등반하는 **덱빌딩 로그라이크**. 김용 원작(사조삼부곡·천룡팔부)의 강호를 무대로 삼되, 주인공은 매 회차 문파 출신이 달라지는 무명인이다. 원작 인물은 사부·동행·관문 보스로 등장한다.

기존 프로젝트 [`Flyest1/sajo-game`](https://github.com/Flyest1/sajo-game)(같은 원작 기반 SRPG)의 세계관·무공 상성·초상 자산·PWA 배포 스택을 참고하되, **장르와 코드베이스는 완전히 새로 만든다.** sajo-game의 코드를 가져오지 않는다.

- 레포: `Flyest1/gangho-bigeup` (신규 생성 필요)
- 배포: `https://flyest1.github.io/gangho-bigeup/`
- 구동: PWA (설치 가능 · 오프라인 플레이)
- 언어: 한국어
- 표기: 비공식·비영리 팬메이드

### 1.1 범위 (1.0)

| 항목 | 분량 |
|---|---|
| 문파(플레이어블) | 3종 |
| 막 | 3막, 막당 12~15노드 |
| 초식 카드 | 약 140장 (문파별 40 + 공용 20) |
| 기물(유물) | 60종 |
| 심법 | 문파당 3종 = 9종 |
| 관문 보스 | 9명 (막당 3명 중 랜덤 1명) + 진최종 1명 |
| 기연 이벤트 | 40종 |
| 승단(난이도) | 15단 |

### 1.2 비목표 (1.0에서 하지 않는 것)

- 온라인 기능 일체 (랭킹, 계정, 서버). 전부 클라이언트 로컬.
- 원작 인물을 조작하는 플레이 (원작 인물은 NPC/보스 전용).
- 그리드 전술 전투 (sajo-game의 영역이며 의도적으로 겹치지 않는다).
- 동행/파티 시스템. 플레이어 유닛은 항상 1명.

## 2. 전투 규칙

플레이어 1명 대 적 1~4체의 턴제 카드 전투.

### 2.1 턴 구조

플레이어 턴:
1. 호신강기 0으로 소멸 (유지 효과가 있으면 예외)
2. 상태이상 턴 시작 처리 (중독 피해 등)
3. 내공을 최대치로 회복 (기본 최대 3)
4. 5장 드로우
5. 플레이어가 카드를 내거나 턴 종료
6. 턴 종료 시 손패 전부 버림

적 턴:
1. 각 적이 예고된 의도를 순서대로 실행
2. 다음 의도 결정 및 표시

뽑을 패가 부족하면 버린 패를 시드 RNG로 섞어 뽑을 패로 되돌린 뒤 계속 뽑는다. 양쪽 다 비면 그 시점에서 드로우를 중단한다.

### 2.2 자원과 방어

- **내공(氣)**: 카드 코스트. 기본 최대 3, 매 턴 최대치로 회복(이월 없음).
- **호신강기(護身罡氣)**: 방어도. 피해를 먼저 흡수하며 플레이어 턴 시작 시 0이 된다.
- **체력(HP)**: 문파별 상이. 0이 되면 런 종료.

### 2.3 자세(勢)와 상성 — 핵심 기믹

이 게임을 여타 덱빌더와 구분하는 축이다.

**계열**: 모든 초식 카드는 `외공(外)` · `경공(輕)` · `내공(內)` 중 하나이거나, 계열이 없는 `술수(術)`다.

**상성**: `외공 ▶ 경공 ▶ 내공 ▶ 외공` (`A ▶ B` = A가 B를 누른다)

**자세**:
- 플레이어의 자세 = 이번 전투에서 마지막으로 낸 계열 카드의 계열. 전투 시작 시에는 문파의 기본 계열.
- 적의 자세 = 그 적이 마지막으로 실행한 계열 행동의 계열. 전투 시작 시에는 적 데이터에 정의된 초기 자세.
- `술수` 카드와 무계열 적 행동은 자세를 바꾸지 않는다.

**판정** (공격이 발생할 때마다, 공격자 계열 대 피격자 현재 자세):
- 공격자 계열이 피격자 자세를 **누르면** → **파훼**: 피해 ×1.5(내림), 그리고 피격자의 호신강기를 무시하고 체력에 직접 적용
- 피격자 자세가 공격자 계열을 **누르면** → 피해 ×0.75(내림)
- 같은 계열이거나 어느 한쪽이 무계열 → 보정 없음

이 규칙은 **적이 플레이어를 공격할 때도 동일하게 적용된다.** 따라서 플레이어의 자세는 공격 효율뿐 아니라 피해 감소에도 직결되며, 자세 관리가 곧 공수 양면의 판단이 된다.

**선(先) 읽기**: 적의 의도 표시에는 다음 행동의 타입·수치와 함께 **계열 아이콘**이 포함된다. 적이 행동하면 그 계열이 곧 다음 턴 적의 자세가 되므로, 플레이어는 "적이 다음 턴 경공 자세가 되니 지금 외공 카드를 손에 남겨둔다" 같은 **카드 순서 퍼즐**을 풀게 된다. 카드를 내는 순서 자체가 매 턴 의미를 가진다는 점이 기존 덱빌더와의 결정적 차이다.

### 2.4 연계(連繫)

- 연계 카운터는 전투 내내 유지된다 (턴 종료로 초기화되지 않음).
- 카드를 낼 때 **먼저 카운터를 갱신하고, 그 다음 보너스 발동 여부를 판정한다.** 같은 계열이면 +1, 다른 계열이면 1로 리셋. `술수` 카드는 카운터를 바꾸지 않고 판정도 하지 않는다.
- 갱신 후 카운터가 **3 이상이면** 그 카드의 효과에 해당 계열의 연계 보너스가 더해진다. 즉 같은 계열 3번째 카드부터 매 장 발동한다.
  - 외공 연계: 이번 카드의 피해 +6
  - 경공 연계: 카드 1장 드로우
  - 내공 연계: 호신강기 +5

상성을 노려 계열을 갈아타면 파훼는 얻지만 연계가 끊긴다. 이 긴장이 매 턴의 실질적 선택을 만든다.

### 2.5 상태이상

| 이름 | 효과 | 감소 |
|---|---|---|
| 중독(毒) | 턴 시작 시 스택만큼 체력 피해 (호신강기 무시) | 턴당 1 |
| 내상(內傷) | 다음 턴 최대 내공 −(스택) | 발동 시 전량 소모 |
| 취약(破) | 받는 피해 +50% | 턴당 1 |
| 쇠약(衰) | 주는 피해 −25% | 턴당 1 |
| 기세(氣勢) | 공격 피해 +스택 | 영구 (전투 한정) |
| 잔상(殘像) | 받는 공격 1회를 완전 회피 | 발동 시 1 |

피해 계산 순서: `기본값 → 기세 가산 → 쇠약 → 취약 → 상성 보정 → 잔상 → 호신강기(파훼면 생략) → 체력`

### 2.6 문파 3종

| 문파 | 기본 계열 | HP | 시작 내공 | 승리 공식 |
|---|---|---|---|---|
| 개방(丐幇) | 외공 | 80 | 3 | 연계 스택을 길게 쌓아 항룡 계열 초대형 일격 |
| 고묘파(古墓派) | 경공 | 65 | 3 | 저코스트 다단타 + 은침 중독, 손패 회전 |
| 소림(少林) | 내공 | 95 | 3 | 호신강기를 축적해 반격 피해로 전환 |

각 문파는 고유 초식 40장과 심법 3종을 가진다. 심법은 시작 시 지급되는 특수 기물이자 패시브이며 빌드 방향을 규정한다 (예: 개방 `취권` — 체력이 낮을수록 피해 증가).

### 2.7 카드 등급과 저주

초식 등급은 `기본(基)` · `상용(常)` · `희귀(稀)` · `절기(絶)` 네 단계다. 보상과 장터의 등장 확률이 등급에 따라 다르며, 문파 시작 덱은 기본 등급으로만 구성된다.

**저주(咀呪)** 는 덱을 오염시키는 별도 카드 부류다. 등급 체계 밖에 있고 보상 선택지로 나오지 않으며, 특정 기연·기물·승단 효과로만 덱에 들어온다. 강화할 수 없고 장터에서 제거하려면 일반 카드보다 비싸다.

- `번뇌(煩惱)`: 낼 수 없음. 손에 있으면 턴 종료 시 체력 2 피해.
- `내상흔(內傷痕)`: 낼 수 없음. 손에 있는 동안 최대 내공 −1.
- `주저(躊躇)`: 낼 수 없음. 뽑을 때 카드를 1장 덜 뽑는다.

## 3. 등반 구조

### 3.1 노드 맵

막마다 시드로 생성되는 분기 경로. 층(層) 단위로 배열되며 각 층에 2~4개 노드, 총 12~15 노드. 인접 층 사이에만 간선이 생기고 최소 1개 완주 경로를 보장한다.

노드 타입: `격전` · `정예` · `기연` · `객잔` · `장터` · `비급` · `관문`

- 1층은 항상 `격전`, 마지막 층은 항상 `관문`, 관문 직전 층은 항상 `객잔`
- 나머지 층 가중치: 격전 45 / 정예 15 / 기연 20 / 객잔 12 / 장터 8
- `비급`(무료 초식 획득)은 막당 정확히 1개를 중간 층에 배치
- 같은 타입이 한 경로에서 3연속 배치되지 않도록 재추첨

### 3.2 막 구성

| 막 | 무대 | 관문 보스 후보 |
|---|---|---|
| 1막 | 강남·우가촌·흑풍 | 매초풍 · 구천장 · 팽련호 |
| 2막 | 도화도·종남산·전진교 | 구천인 · 금륜법왕 · 이막수 |
| 3막 | 화산·광명정·소림 | 구양봉 · 정춘추 · 모용복 |

관문 보스는 **2단계 패턴**을 가진다 (체력 50% 이하에서 행동표·자세 경향이 전환되며 전용 연출이 나온다). sajo-game의 보스 2단계 설계를 계승한 지점이다.

### 3.3 노드별 상호작용

- **격전**: 승리 시 초식 3장 중 1택(넘김 가능) + 엽전
- **정예**: 승리 시 위 보상 + 기물 1
- **관문**: 기물 1(희귀) + 심법 교체 기회 + 엽전 다수
- **객잔**: 휴식(최대 체력의 30% 회복) 또는 수련(초식 1장 강화) 중 택 1
- **장터**: 초식·기물 구매, 엽전으로 덱에서 카드 1장 제거
- **기연**: 원작 사건을 각색한 텍스트 이벤트와 선택지. 40종.
- **비급**: 문파 초식 3장 중 1장을 무료 획득

## 4. 메타 진행

하이브리드 방식. 초반 약 6회차 동안만 해금이 이어지고, 이후에는 순수 난이도 상승(승단)만 남는다.

### 4.1 해금 (강호록)

| 조건 | 해금 |
|---|---|
| 개방으로 1막 클리어 | 고묘파 |
| 아무 문파로 2막 클리어 | 소림 |
| 첫 완주 | 승단 모드 · 기물 2군(20종) |
| 각 문파 첫 완주 | 해당 문파 심법 2번째 |
| 각 문파 승단 5 완주 | 해당 문파 심법 3번째 |
| 승단 15 완주 | 진최종 「제2차 화산논검」 |

기물 1군(40종)과 기연 전체는 처음부터 풀에 있다.

### 4.2 승단(昇段) 15단

완주할 때마다 해당 문파의 승단이 1 오른다. 각 단은 누적된다.

1. 정예 노드 +1
2. 일반 적 체력 +10%
3. 장터 가격 +10%
4. 시작 체력 −5%
5. 보상 초식 선택지 중 1장이 저주 확률
6. 객잔 회복량 −10%p (30%→20%)
7. 보스 체력 +10%
8. 엘리트 자세 전환 빈도 증가
9. 시작 시 저주 「번뇌」 1장 추가
10. 상태이상 감소 속도 −1턴 (2턴에 1 감소)
11. 일반 적 피해 +10%
12. 기물 등장률 −15%
13. 3막 관문 보스가 2단계에서 전용 오의 획득
14. 모든 전투의 첫 턴에만 내공이 3이 아닌 2로 시작
15. 진최종 보스 「제2차 화산논검」 개방 및 강화

## 5. 기술 설계

### 5.1 스택

- **Vite** + **TypeScript** (프레임워크 없음, DOM 직접 조작)
- **vite-plugin-pwa** (Workbox 프리캐시, 오프라인 플레이)
- **Vitest** (엔진 단위 테스트) + **Playwright** (브라우저 스모크)
- **GitHub Actions** → **GitHub Pages** 자동 배포
- 런타임 의존성 0 (연출 라이브러리 없이 CSS 트랜지션 + Web Animations API)

TypeScript를 쓰는 이유: 덱빌더는 규칙 엔진의 사소한 버그가 곧 게임 붕괴로 이어지며, 카드·기물·상태이상의 효과 조합이 조합적으로 늘어난다. 타입으로 효과 스키마를 강제하는 편이 값싸다.

```
  check_engine_purity.mjs  engine/ 안의 DOM 참조 금지 강제
```

**불변 규칙**: `src/engine/` 아래 어떤 파일도 `document` · `window` · `localStorage`를 참조하지 않는다. CI에서 `check_engine_purity.mjs`가 이를 강제한다. sajo-game의 `game.js`가 20만 자 단일 파일로 커진 사례를 참고해, 경계를 처음부터 기계적으로 강제한다.

**엔진 인터페이스**: 전투는 `applyAction(state, action) => state`, 런 진행은 `applyRunAction(runState, action) => runState` 형태의 순수 함수로 노출한다. UI는 상태를 읽어 그리고 액션을 보낼 뿐 규칙을 알지 못한다. 덕분에 엔진은 브라우저 없이 테스트·시뮬레이션 가능하다.

### 5.3 결정적 RNG

런 시작 시 시드 하나를 정하고, 맵 생성·보상 추첨·적 편성·카드 셔플·기연 선택은 모두 그 시드에서 파생된 스트림을 쓴다. 같은 시드와 같은 액션 열은 항상 같은 결과를 낸다. 이로써 밸런스 시뮬, 버그 재현, 완주 기록 공유가 성립한다.

### 5.4 데이터 형식

카드·기물·적·기연은 `src/data/*.json`에 선언한다. 효과는 임의 코드가 아니라 **이름 붙은 효과 원자(effect atom)의 배열**로 표현한다.

```json
{
  "id": "hangryong_youhoe",
  "name": "항룡유회",
  "hanja": "亢龍有悔",
  "school": "gaebang",
  "line": "wai",
  "cost": 3,
  "rarity": "rare",
  "text": "34 피해. 연계 3 이상이면 대상에게 취약 2.",
  "effects": [
    { "op": "damage", "value": 34 },
    { "op": "ifCombo", "min": 3, "then": [{ "op": "applyStatus", "status": "vulnerable", "value": 2 }] }
  ],
  "upgrade": { "effects": [{ "op": "damage", "value": 45 }] }
}
```

효과 원자 집합은 엔진에 고정되어 있고 `tools/validate_data.mjs`가 모든 데이터를 이 스키마에 대해 검증한다. 콘텐츠 추가는 JSON만 고치면 되고 엔진 코드를 건드리지 않는다.

### 5.5 저장

- `localStorage` 키 `gangho.save.v1`
- 구조: `{ version, meta: { unlocks, ascension, stats, achievements }, run: RunState | null }`
- 진행 중 런은 **전체 스냅샷**으로 저장한다 (노드 이동 시점 및 전투 턴 종료 시점마다). 앱을 닫아도 이어서 플레이한다.
- 쓰기 전에 전체 구조를 검증하고, 손상이 감지되면 해당 구획을 격리한 뒤 복구 UI를 띄운다. 저장 전체를 날리지 않는다.
- JSON 내보내기·가져오기 지원.
- `version` 필드로 마이그레이션한다. 하위 버전 저장은 파괴하지 않고 변환한다.

### 5.6 아트 · 사운드

- 인물 초상은 sajo-game의 `public/portraits/` WebP 중 **이 게임에 등장하는 인물분만** 복사해 쓴다 (보스 10명 + 사부·기연 NPC 약 25명 = 35장 내외). 로드 실패 시 SVG 대체 얼굴로 폴백한다.
- 카드 아트는 이미지가 아니라 **코드 생성 SVG 문양 + 서예 타이포**로 만든다. 계열별 문양(검격/바람/기운), 희귀도별 테두리, 한자 대자(大字) 조합. 카드 140장에 이미지 자산 0이 든다.
- 배경은 수묵 그라디언트 + 절차 생성 산세 실루엣.
- 사운드는 WebAudio 절차 합성. 외부 오디오 파일 없음.
- 저효과 모드에서 파티클·화면 흔들림·컷인을 줄인다.

### 5.7 반응형 · 조작 · 접근성

- **모바일 세로 우선.** 손패는 하단 부채꼴, 적은 상단, 자세·연계 표시는 중앙 띠. 데스크톱 가로에서는 같은 배치를 넓게 편다.
- 키보드: 숫자 1~9로 카드 선택, 방향키로 대상 이동, `Space` 턴 종료, `Esc` 취소, `Tab` 순환. 게임패드 기본 대응.
- 계열은 **색·한자·도형 세 가지로 동시 표기**한다. 색만으로 구분하게 두지 않는다 (색각 이상 대응).
- 모달은 초점을 가두고 닫을 때 원래 위치로 되돌린다.

## 6. 테스트 · CI

### 6.1 테스트

- **Vitest 단위**: 상성 판정표(3×3 전 조합 + 무계열), 연계 카운터 전이, 피해 계산 순서, 호신강기 흡수·파훼, 상태이상 감소, 기물 훅 발동, 맵 생성 제약(완주 경로 존재·연속 제한), 저장 마이그레이션·손상 격리
- **시나리오 스냅샷**: 고정 시드로 정해진 액션 열을 재생해 최종 상태를 스냅샷 비교. 규칙 변경 시 회귀를 즉시 잡는다.
- **Playwright 스모크**: 런 시작 → 전투 승리 → 보상 → 저장 후 새로고침 복구 → 오프라인 재기동. 데스크톱·모바일 뷰포트 양쪽.
- **밸런스 시뮬** (`npm run balance`): 휴리스틱 AI가 시드 1000회를 자동 플레이해 문파별 승률, 평균 도달 층, 카드별 채택률을 리포트한다.

### 6.2 CI 파이프라인

`main` 푸시 → `validate` → `typecheck` → `vitest` → `check:purity` → `build` → `verify:build`(PWA 앱 셸·프리캐시 검증) → `playwright smoke` → Pages 배포.

## 7. 구현 단계

| 단계 | 내용 | 완료 조건 |
|---|---|---|
| P1 | 엔진 코어(RNG·자세·연계·상태·전투) + 개방 1문파 + 축약 3막(막당 8노드) + 보스 3 + 카드 60 + 기물 20 + 저장 + PWA 배포 | 배포된 URL에서 개방으로 완주 가능. 엔진 단위 테스트 통과 |
| P2 | 3막 정규화(12~15노드) + 보스 9 + 기물 60 + 기연 40 + 장터·객잔·비급 완성 | 세 막 모두 정상 분기, 데이터 검증 통과 |
| P3 | 고묘파 · 소림 (카드 80장, 심법 6종) | 세 문파 모두 완주 가능, 밸런스 시뮬 승률 리포트 확보 |
| P4 | 메타 진행 · 강호록 · 승단 15단 · 진최종 보스 | 해금 조건 전부 도달 가능 |
| P5 | 연출 · WebAudio · 저효과 모드 · 게임패드 · 접근성 마감 | Playwright 스모크 데스크톱·모바일 통과 |

각 단계 끝에서 배포한다. P1 시점부터 플레이 가능한 상태를 유지한다.

**이 설계서에 이어지는 첫 구현 계획의 범위는 P1이다.** P2~P5는 각각 별도의 계획으로 다룬다. 이 설계서는 다섯 단계 전체의 목표 상태를 기술하되, 한 번에 구현하지 않는다.
